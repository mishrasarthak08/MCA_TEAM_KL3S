## Recording Plan

### 0:00–0:25 Project Idea

**Speaker:** Sarthak Mishra
**Show:** Repository title and report title.

> “Our project is Instruction and Data Memory Hierarchy. We implemented a simplified Harvard organization with separate instruction and data memories and connected it to a single-cycle 32-bit MIPS processor. The main question we test is whether instruction fetch and data access can be handled simultaneously without competing for one memory port.”

**Speaker:** Shitanshu Tiwari

> “We are Team KL3S: Sarthak Mishra, enrolment 2401010421; Shitanshu Tiwari, 2401010440; Shane Joseph, 2401020062; Lakshay Yadav, 2401010250; and Kshitiz Surana, 2401010242.”

### 0:50–1:25 Architecture

**Speaker:** Shane Joseph
**Show:** `report/figures/harvard_architecture.png`, then `docs/block_diagram.mmd`.

> “The program counter addresses a dedicated 256-word instruction ROM. The instruction drives decode, register selection, the ALU, and next-PC logic. Loads and stores use a separate 256-word data RAM through an ALU-generated byte address. Because the two memories have independent paths, a data access does not consume the instruction-fetch port. Both memories detect unaligned and out-of-range addresses.”

### 1:25–1:55 RTL Walkthrough

**Speaker:** Lakshay Yadav
**Show:** `rtl/instruction_memory.v`, `rtl/data_memory.v`, and `rtl/mips_system.v`.

> “The instruction memory is combinational-read ROM, while data memory uses combinational reads and synchronous writes. Both convert byte addresses to word indices using bits 31 through 2. The top-level system connects them to distinct core interfaces. Explicit image-length parameters also make initialization clean and warning-free.”

### 1:55–2:30 Harvard vs Shared-Port Test

**Speaker:** Kshitiz Surana
**Show:** `rtl/shared_memory_arbiter.v`, `testbench/tb_memory_hierarchy.v`, then run `make test-hierarchy`.

> “For comparison, we added a one-port reference arbiter. When instruction and data requests arrive together, it grants only the data request and the fetch must wait. Our trace contains five instruction fetches and two data reads. The Harvard paths complete seven services in five processor cycles, while the shared port needs seven service slots. All six comparison checks pass.”

### 2:30–3:00 Complete Regression

**Speaker:** Shitanshu Tiwari
**Show:** Run `make test`, then show `reports/simulation_results.md`.

> “The complete verification run contains nine self-checking testbenches. It checks the ALU, register file, decoder, memory safety, branch and jump logic, invalid instructions, the architecture comparison, and both full programs. The reproduced result is 95 out of 95 checks passed with zero failures.”

### 3:00–3:30 Array Sum Demo

**Speaker:** Sarthak Mishra
**Show:** Run `make demo-sum`; pause on cycle 36 and the final summary.

> “The first program sums 3, 1, 4, 1, and 5. It repeatedly loads from data memory, accumulates the values, and stores the final result at byte address 20. At cycle 36, the store writes decimal 14. The testbench confirms both memory word 5 and register s0 contain 14.”

### 3:30–4:00 Maximum Search Demo

**Speaker:** Shane Joseph
**Show:** Run `make demo-max`; pause on cycles 16 and 36.

> “The second program searches 7, 2, 11, 4, and 9. Signed SLT comparisons update the candidate when 11 is found at cycle 16. At cycle 36, the program stores 11 at byte address 20. The testbench confirms memory and register s0 both contain the expected maximum.”

We do not claim FPGA frequency, timing, or power because place-and-route was not performed.”
