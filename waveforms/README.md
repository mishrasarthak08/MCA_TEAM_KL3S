# Waveform Inspection and Analysis Guide

This directory contains Value Change Dump (`.vcd`) waveform artifacts generated by Icarus Verilog (`iverilog` / `vvp`) during simulation, along with pre-configured GTKWave visualization profiles.

---

## 1. Available Waveform Dumps

| File | Description | Key Verified Signals |
|---|---|---|
| `mips_cpu_array_sum.vcd` | Complete CPU execution of **Program 1: Array Sum** | `current_pc`, `instruction`, `alu_result`, `dmem_addr`, `dmem_write_data`, `write_reg`, `write_data` |
| `mips_cpu_max_search.vcd` | Complete CPU execution of **Program 2: Maximum Search** | `current_pc`, `instruction`, `alu_result` (SLT comparisons), `branch_taken`, `dmem_write` |
| `tb_alu.vcd` | Unit verification of the 32-bit ALU | `a`, `b`, `alu_ctrl`, `result`, `zero` across signed and unsigned edge cases |
| `tb_register_file.vcd` | Dual-port asynchronous read and synchronous write testing | `read_reg1`, `read_reg2`, `write_reg`, `write_data`, `$zero` protection |
| `tb_decoder.vcd` | Opcode and ALU control decoding verification | `opcode`, `funct`, `reg_dst`, `alu_src`, `alu_op`, `invalid_opcode` |
| `tb_memory.vcd` | Memory alignment, bounds checking, and read/write | `addr`, `read_data`, `write_data`, `alignment_error`, `out_of_bounds` |
| `tb_memory_hierarchy.vcd` | Harvard concurrency and shared-port contention comparison | `instruction`, `dmem_read_data`, `instruction_request`, `data_request`, `instruction_grant`, `data_grant`, `contention` |
| `tb_branch_jump.vcd` | Next-PC multiplexer, branch adder, and jump logic | `pc`, `pc_plus_4`, `branch_target`, `jump_target`, `take_branch`, `next_pc` |
| `tb_invalid_instr.vcd` | Architectural robustness and write suppression | `test_instruction`, `invalid_instruction`, `debug_reg_write`, `dmem_write` |

## 2. Viewing Waveforms with GTKWave

To open the master CPU execution waveform with pre-configured grouped signals in GTKWave:

```bash
gtkwave waveforms/mips_cpu_array_sum.vcd waveforms/mips_cpu.gtkw
```

For the Maximum Search program:

```bash
gtkwave waveforms/mips_cpu_max_search.vcd waveforms/mips_cpu.gtkw
```

## 3. Interpreting Waveforms

### Signal Hierarchy and Grouping

1. **Clock and Reset**:
   - `tb_mips_cpu.clk`: System master clock (100 MHz, 10 ns period).
   - `tb_mips_cpu.rst`: Asynchronous active-high reset, asserted for the first 20 ns.

2. **Program Counter (PC) & Instruction**:
   - `tb_mips_cpu.current_pc`: Byte address of current instruction (0x00, 0x04, 0x08, ...).
   - `tb_mips_cpu.current_instruction`: 32-bit machine code fetched from Instruction Memory.

3. **Control Signals**:
   - `reg_dst`: High for R-type (writes to `rd`); low for I-type (writes to `rt`).
   - `alu_src`: High for immediate operands (`ADDI`, `LW`, `SW`); low for register operands.
   - `mem_to_reg`: High for `LW` (loads from memory); low for ALU computations.
   - `safe_reg_write`: Gated write-enable preventing corruption by invalid opcodes.
   - `safe_mem_write`: Gated memory-write enable for `SW`.
   - `branch_taken`: Asserted on clock cycle where `BEQ` condition evaluates true (`Branch & Zero`).
   - `jump_taken`: Asserted when opcode is `J`.

4. **Register File Transactions**:
   - Observe `read_reg1` (`rs`) and `read_reg2` (`rt`) providing operands combinatorially.
   - Observe `write_reg` and `write_data` latching on `posedge clk` when `reg_write` is active.
   - Confirm register `$0` (`$zero`) always evaluates to `0x00000000`.

5. **ALU Computation**:
   - `alu_operand_b`: Multiplexed between sign-extended immediate and register data 2.
   - `alu_result`: 32-bit arithmetic/logic output.
   - `alu_zero`: High whenever `alu_result == 0`.

6. **Memory Interface**:
   - `dmem_addr`: Driven by `alu_result`.
   - `dmem_write_data`: Driven by `read_data2`.
   - `dmem_write`: Single-cycle active-high pulse during `SW`.
   - `dmem_read_data`: Combinational output valid during `LW`.

## 4. Key Execution Milestones in Waveforms

### Program 1: Array Sum
- **Cycles 1–4**: Register initialization (`$t0=0`, `$t1=0`, `$t2=5`, `$s0=0`).
- **Cycles 5–34**: Loop execution. In each 6-cycle iteration:
  - `LW` loads element from memory address `$t0`.
  - `ADD` accumulates into `$s0`.
  - `ADDI` increments `$t0` by 4 and `$t1` by 1.
  - `J` loops back to evaluation.
  - Intermediate sums in `$s0`: `3` -> `4` -> `8` -> `9` -> `14` (`0x0E`).
- **Cycle 35**: `BEQ` evaluates `$t1 == $t2` (5 == 5) -> `Zero` asserted, branch taken to `done`.
- **Cycle 36**: `SW $s0, 0($t4)` writes `0x0000000E` to data memory address `0x00000014` (byte 20).
- **Cycles 37–39**: Processor enters infinite halt loop at `0x00000030`.

### Program 2: Maximum Search
- **Cycles 1–4**: Loads first element `7` into `$s0`, initializes `$t1=1`, `$t2=5`, `$t0=4`.
- **Cycle 7**: Compares `7` and `2` with `SLT` -> result `0`. `BEQ` branches over update.
- **Cycle 14**: Compares `7` and `11` with `SLT` -> result `1`. `BEQ` not taken.
- **Cycle 16**: `ADD $s0, $zero, $t3` updates maximum to `11` (`0x0B`).
- **Cycle 22**: Compares `11` and `4` -> result `0`, skip taken.
- **Cycle 29**: Compares `11` and `9` -> result `0`, skip taken.
- **Cycle 36**: `SW $s0, 0($t5)` writes `0x0000000B` (11) into memory byte address 20.
